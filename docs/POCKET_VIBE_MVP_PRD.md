## 1. 产品概述

### 1.1 产品定位

Pocket Vibe 是一款 Android 优先的 AI 源码阅读器，帮助开发者、大学生和源码学习者在碎片时间通过手机阅读、理解、追踪和沉淀开源项目源码。

MVP 要证明的核心命题：

**手机终于可以认真读代码了。**

### 1.2 MVP 目标

1. 让用户可以从公共 GitHub URL 引入仓库，并在手机上稳定阅读源码。
2. 让用户可以通过函数折叠、搜索、跳转定义、查找引用和阅读轨迹完成基础源码理解。
3. 让用户可以把当前文件、函数、选区作为上下文向 AI 提问。
4. 让用户可以把 AI 回答和手动理解沉淀为 Markdown 笔记、代码批注和学习日报。

### 1.3 MVP 非目标

- 不做手动编码。
- 不允许 Agent 改代码。
- 不做 Git commit / branch / PR。
- 不做 GitHub 登录。
- 不支持私有仓库。
- 不支持本地目录导入。
- 不做语音输入。
- 不做 Skill marketplace。
- 不做高级商业化。
- MVP 不交付 ArkTS/ETS 原生端。
- MVP 不交付 HarmonyOS NEXT 原生应用；但后续版本明确纳入适配目标。

### 1.4 目标用户

- 有源码学习需求的工程师。
- 大学生和编程学习者。
- 希望在通勤、睡前、咖啡店等碎片时间读代码的人。
- 使用 Android 手机、希望在手机上更高频接触代码的人。

### 1.5 优先级定义

- P0：MVP 必须交付，否则无法完成核心闭环。
- P1：MVP 可带上，但不阻塞首版验证；若排期紧张可延后到 v0.2。

### 1.6 平台与鸿蒙适配口径

MVP 平台策略为 **Android 优先，后续适配 HarmonyOS NEXT / 原生鸿蒙**。

Android Native Kotlin/Java 方案可以作为 Android MVP 的主实现路线；在仍具备 Android 兼容层的鸿蒙设备上，APK 形态通常可以运行，但这不等同于 HarmonyOS NEXT 原生应用适配。

HarmonyOS NEXT / 原生鸿蒙不应假设可以直接运行 Android Kotlin/Java、Android SDK、Activity/View 或 APK 兼容逻辑。由于后续版本需要适配 HarmonyOS NEXT，MVP 架构必须将 Tree-sitter、ripgrep 搜索、Anchor 定位、符号索引、LSP JSON-RPC client 等能力沉淀为跨平台 Rust/C/C++ core；Android 侧通过 JNI 调用，鸿蒙原生侧通过 NAPI/FFI 调用，并分别实现 Kotlin/Android UI 与 ArkTS/ArkUI UI。

MVP 验收不以 HarmonyOS NEXT 原生运行作为交付标准，但技术验收需要检查核心逻辑是否与 Android UI 层解耦，避免后续适配时重写 Tree-sitter、搜索、Anchor 和 LSP 核心能力。

## 2. 核心用户故事

### 2.1 P0 用户故事

1. 作为一个有源码学习需求的工程师，我希望粘贴一个公共 GitHub 仓库 URL 并 clone 到手机本地，以便于在碎片时间打开并阅读源码。
2. 作为一个源码学习者，我希望 App 能展示本地仓库列表和最近打开文件，以便于我下次继续从上次位置阅读。
3. 作为一个手机端读码用户，我希望代码能语法高亮并按函数/方法折叠，以便于在小屏幕上先看结构，再逐步展开细节。
4. 作为一个源码学习者，我希望看到函数长度、注释/docstring 摘要和 sticky 当前函数名，以便于快速判断当前代码块的作用和阅读位置。
5. 作为一个工程师，我希望点击符号时可以准确跳转定义，以便于追踪代码实现。
6. 作为一个工程师，我希望可以查找引用并查看候选结果，以便于理解函数或类型在项目中的使用方式。
7. 作为一个读源码的人，我希望搜索结果可以先半屏预览再跳转，以便于避免频繁打断当前阅读位置。
8. 作为一个手机端用户，我希望阅读过程中有前进/后退轨迹和文件卡片视图，以便于从多次跳转后快速回到原来的上下文。
9. 作为一个读源码的人，我希望打开 Chat 浮层，并把当前文件、函数或选区加入上下文，以便于向 AI 提问并获得针对当前代码的解释。
10. 作为一个关注成本的用户，我希望在发送 AI 问题前看到 token / 费用粗略估算，以便于决定是否调整上下文。
11. 作为一个源码学习者，我希望把 AI 回答保存为 Markdown 笔记，以便于后续复习和沉淀理解。
12. 作为一个在代码旁做学习记录的用户，我希望笔记能绑定到具体代码位置，以便于之后从笔记跳回原始源码位置。
13. 作为一个持续学习的用户，我希望 App 自动生成学习日报，以便于看到今天读过哪些文件、问过哪些问题、沉淀了哪些笔记。
14. 作为一个经常在无网络环境下通勤的用户，我希望已 clone 仓库可以离线阅读，以便于网络不可用时仍能看源码。

### 2.2 P1 用户故事

1. 作为一个进阶用户，我希望自定义快捷 Skill，以便于把常用读码 prompt 变成快捷操作。
2. 作为一个多设备用户，我希望登录账号同步笔记、chat 历史和配置，以便于更换设备后继续使用。
3. 作为一个源码学习者，我希望保存 AI 回答时同时保留原文和整理版，以便于既能复盘 AI 原始输出，也能查看可读性更强的笔记。
4. 作为一个长期学习者，我希望生成知识卡片，以便于把一次源码理解沉淀成可复用的知识单元。

## 4. 核心业务流程图描述

完整流程：从粘贴 GitHub URL 到看完代码并生成笔记摘要。

1. 用户打开 Pocket Vibe。
   - 如果本地已有仓库，进入本地仓库列表。
   - 如果没有仓库，展示空状态和“粘贴 GitHub URL”入口。

2. 用户粘贴公共 GitHub URL。
   - App 校验 URL 格式。
   - App 判断是否为支持的 GitHub 公共仓库地址。
   - 校验通过后创建 clone 任务。
   - 校验失败则提示“仅支持公共 GitHub 仓库 URL”。

3. App clone 仓库到本地。
   - 展示 clone 进度、速度、当前阶段。
   - clone 成功后写入本地仓库记录。
   - clone 失败时允许重试或删除残留。

4. App 启动基础索引。
   - 后台启动 Tree-sitter 结构识别。
   - 后台启动 LSP 初始化和索引。
   - 准备 ripgrep 搜索能力。
   - 索引不阻塞源码阅读。
   - LSP 未就绪时跳转定义和查找引用按钮不可点击或展示弱 loading。

5. 用户进入仓库阅读页。
   - 若有最近打开文件，直接进入最近打开文件。
   - 若是首次打开，进入默认文件入口或文件树。
   - 阅读页显示顶部当前文件路径、主代码区、隐藏式搜索入口、Chat 浮层入口。

6. 用户阅读代码。
   - 代码语法高亮。
   - 函数/方法默认可折叠。
   - 折叠块展示函数长度和注释摘要。
   - 滚动时 sticky 当前函数名。
   - 用户可全部折叠/全部展开。

7. 用户导航和追踪调用。
   - 点击符号后，如果 LSP 就绪，展示定义跳转或候选定义列表。
   - 用户可查看引用结果。
   - 搜索命中后先半屏预览，再选择跳转。
   - 每次跳转写入浏览轨迹。
   - 用户可通过前进/后退回溯。

8. 用户向 AI 提问。
   - 用户选中代码或定位到当前函数。
   - 用户将文件、函数或选区加入上下文篮子。
   - Chat 浮层展示上下文 chip。
   - 用户点击“解释这段代码”等快捷按钮。
   - App 将 prompt 放入输入框，等待用户确认。
   - 发送前展示 token / 费用粗略估算。

9. AI 返回解释。
   - Chat 浮层展示回答。
   - 回答保存在项目 chat 历史中。
   - 用户可继续追问，或从回答中的代码引用跳转回主阅读区。

10. 用户沉淀笔记。
    - 用户点击“保存为笔记”。
    - App 生成 Markdown 笔记草稿。
    - 笔记绑定当前文件、函数或选区 anchor。
    - 用户可编辑标题和正文后保存。

11. App 更新学习日报。
    - 记录用户读过的文件、停留时间、搜索/跳转行为、问题数量、保存笔记数量。
    - 当天日报自动生成。
    - 用户可从笔记页查看日报摘要。

12. 同步与离线。
    - 未登录用户数据保存在本地。
    - 登录用户同步笔记、chat 历史和配置。
    - API key 不同步。
    - 无网络时，已 clone 仓库和本地笔记仍可查看。

## 5. 异常与边界情况定义

### 5.1 代码引入与仓库管理

| 场景 | 处理规则 |
|---|---|
| GitHub URL 格式错误 | 阻止提交，提示正确示例。 |
| 私有仓库 URL | MVP 不支持，提示“当前仅支持公共 GitHub 仓库”。 |
| 非 GitHub URL | MVP 不支持，提示支持范围。 |
| clone 过程中断网 | clone 任务失败并允许重试；不得留下不可删除的半成品仓库。 |
| clone 过程中 App 进入后台或锁屏 | 尽量继续任务；如被系统终止，下次打开展示失败/可重试状态。 |
| 仓库过大 | clone 前或 clone 中提示仓库体积风险；本地空间不足时中止并清理残留。 |
| Git LFS / submodule | MVP 可不完整支持；需提示“部分资源可能未下载”。 |
| 文件编码异常 | 尝试 UTF-8；失败时以只读纯文本或错误态展示。 |
| 二进制文件 | 不进入代码阅读器，展示“暂不支持预览”。 |

### 5.2 阅读与导航

| 场景 | 处理规则 |
|---|---|
| LSP 初始化慢 | 不阻塞阅读；跳转定义/查找引用展示弱 loading 或不可点击。 |
| LSP 初始化失败 | 代码仍可阅读；LSP 相关按钮不可点击，并提供失败原因和重试入口。 |
| 索引未完成 | 不允许用户点击尚不可用的定义/引用入口，避免产生不可靠结果。 |
| Tree-sitter 解析失败 | 文件退化为语法高亮或纯文本阅读；折叠功能不可用。 |
| 不支持语言 | 可阅读、可搜索、可问 AI；不承诺准确跳转定义和引用查找。 |
| 超大文件 | 限制一次渲染范围或提示性能风险；保证 App 不崩溃。 |
| 横竖屏切换 | 保存当前文件、滚动位置、折叠状态、选区、Chat 浮层状态。 |
| 文件被删除或仓库更新后位置失效 | 尝试通过文件路径、symbol、代码片段 hash、commit hash 恢复；失败则提示位置已失效。 |
| 搜索结果过多 | 分页或限制展示数量，优先展示文件路径和片段；不阻塞主阅读区。 |

### 5.3 AI Chat 与上下文

| 场景 | 处理规则 |
|---|---|
| 未配置 API key | Chat 输入可编辑，但发送时提示配置模型服务。 |
| API key 无效 | 展示模型服务返回的失败原因，并提供重新配置入口。 |
| 无网络 | 禁用发送；允许查看历史 chat 和本地笔记。 |
| 模型超时 | 展示重试入口；不得重复扣上下文或重复插入消息。 |
| 上下文篮子超出 token 限制 | 发送前阻止发送，并提示移除部分 chip 或缩短选区。 |
| 费用估算过高 | 发送前提示用户确认或裁剪上下文。 |
| chip 对应代码位置失效 | chip 标记为失效，可移除；不阻塞其他上下文发送。 |
| Chat 浮层遮挡代码 | 半屏浮层出现时主代码区需要避让，避免当前阅读行被完全遮住。 |
| 全屏 Chat 退出 | 回到进入 Chat 前的文件和滚动位置。 |

### 5.4 知识沉淀

| 场景 | 处理规则 |
|---|---|
| 保存笔记失败 | 保留草稿，提示重试；不得丢失用户编辑内容。 |
| anchor 定位失败 | 笔记仍可打开；代码跳转提示“原位置无法恢复”。 |
| 用户删除仓库 | 同步删除该项目本地阅读状态；是否删除笔记需二次确认。 |
| 日报无数据 | 当天无学习行为时不生成日报，或展示空日报状态。 |
| 同步冲突 | MVP 可采用最后修改时间优先；冲突版本保留为副本。 |
| API key 同步 | 明确禁止同步 API key，只保存在本机安全存储。 |
| 源码隐私 | MVP 仅支持公共仓库；同步 chat 历史时需在隐私说明中告知可能包含源码片段。 |

## 7. MVP 验收口径

### 7.1 P0 闭环验收

MVP 必须完成以下闭环：

1. 用户粘贴公共 GitHub URL。
2. App clone 仓库并进入阅读页。
3. 用户阅读一个源码文件，完成折叠/展开、搜索、跳转定义或引用查找。
4. 用户把当前函数或选区加入上下文篮子。
5. 用户向 AI 提问并收到回答。
6. 用户将回答保存为 Markdown 笔记。
7. 用户可从笔记跳回代码位置。
8. App 当天生成学习日报。

### 7.2 体验底线

- 已 clone 仓库必须支持离线阅读。
- LSP 慢或失败不得阻塞基础阅读。
- Chat 失败不得影响代码阅读和笔记查看。
- 横竖屏切换不得丢失当前阅读状态。
- token 超限必须在发送前被拦截。
- API key 不得云同步。

## 8. 排期建议

### 8.1 第一阶段：阅读闭环

范围：

- 公共 GitHub URL clone。
- 本地仓库列表。
- 最近打开文件。
- 语法高亮。
- 函数/方法折叠。
- 全文搜索。
- 基础阅读状态保存。

交付目标：用户能稳定在手机上打开仓库并读代码。

### 8.2 第二阶段：精准导航闭环

范围：

- LSP 跳转定义。
- LSP 查找引用。
- 跳转候选列表。
- 搜索半屏预览。
- 浏览轨迹前进/后退。
- 文件卡片视图。

交付目标：用户能在手机上追踪源码，不迷路。

### 8.3 第三阶段：AI 问答闭环

范围：

- Chat 半屏/全屏浮层。
- 上下文篮子和 chip。
- 模型配置。
- token / 费用粗略估算。
- 快捷提问入口。
- Chat 历史保存。

交付目标：用户能围绕当前源码向 AI 提问。

### 8.4 第四阶段：知识沉淀闭环

范围：

- Markdown 笔记。
- 保存 AI 回答为笔记。
- 代码位置 anchor。
- 代码批注。
- 学习日报。
- 基础账号与同步。

交付目标：用户能把源码理解沉淀为可回看的知识资产。

## 9. 冷启动与首批用户验证计划

### 9.1 定位原则

冷启动策略属于 MVP 发布配套计划，不作为 P0 产品功能阻塞首版交付。MVP 产品侧优先证明“手机可以认真读代码”，冷启动侧优先证明“目标用户愿意围绕真实开源项目形成持续读码行为”。

冷启动不做泛泛的 App 宣传，重点围绕源码学习场景提供可直接使用的读码路径、打卡机制和可分享成果。

### 9.2 MVP 同期：热门开源仓库读码包

目标：借助高关注开源项目的学习需求，获取第一批对“手机读源码”有明确动机的种子用户。

候选仓库方向：

- React：调度、hooks、reconciler。
- Vue：响应式、compiler、runtime。
- FastAPI：路由、依赖注入。
- Gin：中间件、路由树。
- Spring 示例项目：Java 学生友好。
- Next.js：框架架构。

内容形式：

- “用 Pocket Vibe 在手机上读懂 X 的第 1 天”。
- 每篇只解决一个源码问题，例如入口在哪、核心数据结构是什么、一次请求怎么流动、哪个函数最关键。
- 每篇配套一个可直接 clone 的公共 GitHub 仓库 URL、建议阅读文件、建议提问 prompt 和笔记模板。

发布渠道：

- GitHub Discussions。
- 掘金、知乎、V2EX。
- Reddit 对应技术社区。
- 目标开源项目相关学习社群。

### 9.3 MVP 同期或 v0.2：7 天手机读源码打卡

目标：把 Pocket Vibe 从单纯工具转化为源码学习行为，尤其服务“想变强但坚持不下来”的工程师、学生和编程学习者。

打卡规则：

- 每天 15 分钟。
- 每天围绕一个具体源码问题阅读。
- 用户至少保存一条 Markdown 笔记、代码批注或学习日报记录。
- 第 7 天沉淀一份可分享的学习总结。

产品依赖：

- MVP 已支持 Markdown 笔记和学习日报时，可先手动组织打卡活动。
- v0.2 可增加公开学习卡片、打卡进度和分享图能力。

### 9.4 v0.2 / v0.3：开源轻量读码索引与笔记格式规范

目标：让 Pocket Vibe 的知识沉淀格式成为可迁移、可引用、可社区共创的轻量规范，降低用户对单一 App 的顾虑。

可开源内容：

- `pocketvibe://` anchor 规范。
- Markdown 笔记引用格式。
- 示例仓库学习日报模板。
- 读码路线包的目录结构和元数据格式。

前置条件：

- 代码位置 anchor、笔记、日报的数据结构在 MVP 使用中验证稳定。
- 至少完成 3 个官方读码路线包，避免过早开源空规范。

### 9.5 冷启动验证指标

首批验证不以下载量为唯一指标，优先观察读码行为是否成立：

- 读码包访问到 App clone 的转化率。
- 首次 clone 成功率。
- 首次阅读后 24 小时内再次打开率。
- 单用户 7 天内阅读天数。
- 保存笔记、批注或学习日报的用户占比。
- 用户主动分享学习记录或反馈的数量。
