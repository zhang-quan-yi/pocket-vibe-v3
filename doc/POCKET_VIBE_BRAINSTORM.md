# Pocket Vibe 头脑风暴问答记录

本文档完整记录 Pocket Vibe 产品头脑风暴过程中的追问、回答与阶段性结论。

记录时间：2026-05-08 至 2026-05-13  
项目目录：`D:\work\project-design\pocket-vibe-v3`

## 0. 原始产品描述

Pocket Vibe 是一款移动应用，用于在手机端进行 vibe coding。

- 它有 chat 功能，用于执行 Agent 任务。
- Agent 跑在手机端。
- 它有极其优雅的代码阅读功能。
- 它可以拉取 GitHub 仓库中的代码。

## 1. 阶段性产品结论

Pocket Vibe 的核心不是“手机写代码 IDE”，而是：

**Android 优先的 AI 源码阅读器 + 知识沉淀工具。**

它主要服务于开发者、大学生和有源码学习需求的人，让用户在地铁、床上、咖啡店等碎片时间里读源码、理解架构、追踪调用链、向 AI 提问，并把理解沉淀成 Markdown 笔记、代码批注、知识卡片和学习日报。

第一版重点能力：

- 公共 GitHub 仓库 URL clone。
- 已 clone 代码支持离线阅读。
- 最近打开文件作为项目入口。
- Tree-sitter 做结构识别与函数折叠。
- LSP 做准确跳转定义和查找引用。
- ripgrep 做全文搜索。
- Chat 浮层参考 VS Code Chat / Claude Code。
- 上下文篮子单次提问使用，支持文件、函数、选区等 chip。
- token / 费用粗略估算。
- Markdown 笔记、代码批注、知识卡片、学习日报。
- 账号系统用于同步笔记、chat 历史、配置；API key 不同步。

第一梯队语言：

- JS/TS
- Python
- Go
- Java

第二梯队后续考虑：

- Kotlin/Android
- C/C++

第一版明确不做：

- 手工编码
- Agent 改代码
- branch / commit / PR
- GitHub 登录
- 本地目录导入
- 语音笔记
- ArkTS/ETS
- 高级阅读能力收费
- onboarding 强引导

## 2. 第一轮：产品定位与基础场景

### 2.1 Vibe Coding 的定义

**问：** 你说的 “vibe coding” 在 Pocket Vibe 里具体指什么：写代码、读代码、让 Agent 改代码、还是管理任务？

**答：** 主要是读代码。阅读体验要优化。当然也可以指挥 agent 完成编码任务。不需要支持手工编码。

### 2.2 核心痛点

**问：** 这个产品最想解决的痛点是“电脑不在身边也能推进开发”，还是“手机更适合轻量决策/审阅/指挥 Agent”？

**答：** 想要解决的痛点是读代码，借助大模型能力学习各个代码仓库；想要在空闲时间让 agent 编写、优化设计文档。人工评审后，再让 agent 优化。

### 2.3 App 打开后的第一件事

**问：** 用户打开 App 的第一件事应该是什么？

**答：** 选取项目，本地有项目的话，在本地选。本地没有的话，从 GitHub 上拉取。然后通过 chat 窗口做接下来的事情。

### 2.4 只能保留一个核心功能

**问：** 如果只能保留一个核心功能，你会保留 chat agent、代码阅读、GitHub 拉取、还是手机端运行环境？

**答：** 代码阅读是基础，结合 agent 的代码阅读代码。

### 2.5 产品类比

**问：** Pocket Vibe 更像 Cursor 手机版、GitHub 手机增强版、Replit 手机版，还是一个全新的 Agent 控制台？

**答：** Cursor 手机版 + 源码阅读。Cursor 手机版是看不到源码的。

### 2.6 第一批用户

**问：** 第一批用户是谁：独立开发者、创业者、AI 编程重度用户、通勤时看代码的人、还是不会写代码但会提需求的人？

**答：** 我自己。还有大学生吧。我自己是空闲时间有这个需求。我是一名开发者，想尽可能地多接触代码。平常看文字教程，光看教程没啥用。必须要写代码。但手机写代码不方便，妥协一下，能读也行。上班写工作代码，下班看自己喜欢的代码。

### 2.7 用户能力

**问：** 用户是专业工程师，还是“有产品想法但不会完整开发”的人？

**答：** 用户是工程师。有学习需求的人。

### 2.8 使用场景

**问：** 他们一天中什么时候用：地铁、床上、会议间隙、咖啡店、出门办事时？

**答：** 地铁、床上、咖啡店。

### 2.9 手机上做多复杂的事

**问：** 用户愿意在手机上做多复杂的事：只审阅/批准，还是真的改代码、跑测试、提交 PR？

**答：** 只审阅/批准。不手动写代码。但是可以手动记录点想法吧。学习代码、学习代码仓库。

### 2.10 平台优先级

**问：** 这个产品是给 iPhone 优先，Android 优先，还是跨平台必须同时做？

**答：** Android 优先。因为我是 Android 手机。

### 2.11 Agent 跑在手机端

**问：** “Agent 跑在手机端”是硬要求吗？为什么不能云端跑？

**答：** “Agent 跑在手机端”想要方便而已。跑云端当然也可以，但是会贵吧，有额外费用吧。还有源代码在本地呀。

### 2.12 推理位置

**问：** 手机端 Agent 是真正本地推理，还是本地执行工具、模型走云端？

**答：** 推理肯定是在云端呀。调大模型 API。

### 2.13 Agent 工具能力

**问：** Agent 能访问哪些工具：shell、git、文件系统、包管理器、浏览器、模拟器、数据库？

**答：** Agent 能访问的工具有限吧，毕竟是在手机上。阅读代码肯定需要 git、文件系统吧。

### 2.14 手机性能消耗

**问：** 手机性能、电量、发热、后台限制，你愿意牺牲到什么程度？

**答：** 比打游戏看视频之类的好一些就行。

### 2.15 锁屏任务

**问：** 如果 Agent 在手机上跑 20 分钟任务，用户能锁屏吗？任务是否继续？

**答：** 用户可以锁屏，但是任务继续进行。

### 2.16 Agent 权限边界

**问：** Agent 的权限边界是什么：默认只读、用户批准写入、用户批准执行命令、还是全自动？

**答：** Agent 的权限边界保持业界友商一致就行。

### 2.17 优雅代码阅读

**问：** “极其优雅的代码阅读”具体优雅在哪里：导航快、字体排版、符号跳转、AI 总结、调用链、文件地图？

**答：** 操作、交互适配手机端。智能提示。AI 唤起方便。代码上下文管理快捷。

### 2.18 手机上读代码最难受的点

**问：** 手机上读代码最难受的点，你最想消灭哪一个？

**答：** 文件直接切换，代码位置跳转。

### 2.19 阅读中心

**问：** 代码阅读是以文件为中心、函数为中心、任务为中心，还是 Agent 解释为中心？

**答：** 函数为中心。也可以跟着 agent 解释走。

### 2.20 IDE 能力

**问：** 是否需要 IDE 能力：搜索、跳转定义、引用查找、diff、blame、折叠、语法高亮？

**答：** 需要，必须的。但不一定需要编辑功能。

### 2.21 横屏/竖屏

**问：** 你希望用户横屏读代码吗？还是竖屏必须体验很好？

**答：** 都可以吧。

### 2.22 代码和 chat 共存

**问：** 代码和 chat 如何共存：分屏、浮层、底部抽屉、左右滑动、还是 chat 驱动跳转？

**答：** 浮层。

## 3. 第二轮：源码学习模式

### 3.1 默认模式

**问：** 用户打开一个仓库后，默认应该进入“学习模式”，还是“任务模式”？

**答：** 学习模式。

### 3.2 学习目标

**问：** 学习代码仓库时，你最想完成的是：理解架构、理解某个功能、学习写法、找灵感、还是准备复刻？

**答：** 理解架构、理解某个功能。

### 3.3 仓库类型

**问：** 你会读什么类型的仓库更多：前端、后端、移动端、AI 项目、框架源码、开源工具？

### 3.4 学习路径

**问：** 你希望 App 帮你建立“学习路径”吗？例如：先看入口文件，再看核心模块，再看测试。

**答：** 肯定需要呀，不然要大模型干什么。

### 3.5 随机翻还是带问题读

**问：** 你读源码时，是随机翻，还是带着问题读？

**答：** 大模型来指引。当然也可以带着问题读。

### 3.6 仓库完成状态

**问：** “读完一个仓库”在产品里有没有完成状态？比如生成一份学习笔记/架构图/知识卡片。

**答：** 没有完成状态，这又不是读书。但是需要学习笔记/架构图/知识卡片的。这很有帮助。

### 3.7 文件与函数展示

**问：** 你说“函数为中心”，那首页/代码页是否应该展示函数列表，而不是文件树？

**答：** 打开文件，默认收起所有方法、函数。

### 3.8 函数页面

**问：** 一个函数页里你希望看到什么：源码、解释、调用方、被调用函数、相关文件、测试、变更历史？

**答：** 不需要单独的函数页面。

### 3.9 长函数解释

**问：** 函数很长时，AI 应该自动分段解释吗？

**答：** 不需要，只有主动询问时才解释。但可以自动折叠代码块。

### 3.10 函数调用跳转

**问：** 点击一个函数调用时，是直接跳到定义，还是弹出一个预览浮层？

**答：** 弹出一个新的浮层，可以快捷前进后退。

### 3.11 阅读路径回溯

**问：** 是否需要“阅读路径”：我从 A 函数跳到 B 函数，再跳到 C 函数，可以一键回溯？

**答：** 需要。

### 3.12 后退/前进历史

**问：** 你希望像浏览器一样有后退/前进历史吗？

**答：** 需要，而且操作要便捷，比如增加手势操作。

### 3.13 竖屏读代码

**问：** 竖屏读代码时，你能接受横向滚动吗？还是必须自动换行？

**答：** 都支持，做成可设置的。

**答：** 都支持，做成可设置的。

**问：** 是否需要“收藏函数/文件”？

**答：** 不需要吧。

### 3.18 稍后阅读

**答：** 不需要吧。

**问：** 是否需要代码字体、字号、行高、主题自定义？

**答：** 字体需要的。主题暂时只需要夜间、白天模式。

**问：** 点击函数名展开，长按函数名唤起操作菜单，这样合理吗？

2. 速读密度：展开当前函数，其他函数保持折叠。

## 10. 商业化建议沉淀

建议第一阶段不要围绕模型 API 强收费，而是围绕同步、知识库、专业阅读能力收费。

推荐路径：

- 免费版：公共仓库 clone、本地阅读、基础 LSP、基础 chat、少量笔记。
- Pro 版：同步、无限笔记历史、高级知识卡片、自定义 skill、高级搜索/调用链。
- AI 额度包：可选，给不想填 API key 的用户使用，不替代用户自带 API key。

潜在付费点：

1. 同步会员：同步笔记、chat 历史、配置、skill、学习日报。API key 不同步。
2. 知识库 Pro：跨仓库知识卡片、双链、全局搜索、学习日报历史、知识图谱、Markdown 导出/导入、版本历史。
3. AI Workflow Pro：自定义 skill、高级 skill、skill 模板库、上下文策略、项目级 prompt、模型路由配置。
4. 托管 AI 额度：少量免费额度，超出按量或订阅。
5. 教育版 / 学生包：面向学生和源码学习用户。
6. 团队/组织版：团队共享源码学习笔记、私有知识库、组织配置、权限管理、私有部署。

当前用户倾向：

- 暂时不限制免费公共仓库数量。
- 暂时不对高级阅读能力收费。
- 暂时不对学生收费。
- 未来 Pro 可按月订阅。
- 独立笔记 App 可以单独收费，但暂时不急。

## 11. 可直接转 PRD 的产品骨架

### 11.1 产品定位

Pocket Vibe 是一款 Android 优先的 AI 源码阅读器，帮助开发者在碎片时间通过手机阅读、理解、追踪和沉淀开源项目源码。

### 11.2 目标用户

- 开发者本人。
- 有源码学习需求的工程师。
- 大学生。
- 希望在下班、通勤、睡前读代码的人。

### 11.3 核心使用路径

1. 用户打开 App。
2. 选择本地项目；若本地没有，则粘贴公共 GitHub URL clone。
3. 进入最近打开文件。
4. 通过折叠结构、搜索、跳转定义、查找引用阅读代码。
5. 用 Chat 浮层提问。
6. 将当前文件、函数、选区加入上下文篮子。
7. 通过快捷 Skill 解释代码、查调用链、找相关文件、生成笔记。
8. 将 AI 回复和手动理解沉淀为 Markdown 笔记、代码批注、知识卡片和学习日报。

### 11.4 MVP 必须能力

- 公共 GitHub URL clone。
- 本地仓库列表。
- 最近打开文件。
- 代码语法高亮。
- 函数/方法折叠。
- 函数长度、注释/docstring 摘要。
- sticky 当前函数名。
- 全部折叠/全部展开。
- LSP 级跳转定义。
- LSP 级查找引用。
- 跳转候选列表。
- 搜索结果半屏预览后跳转。
- 文件卡片视图。
- 浏览轨迹前进/后退。
- Chat 浮层半屏/全屏。
- 上下文 chip。
- token / 费用粗略估算。
- 自定义 Skill。
- Markdown 笔记。
- 代码位置 anchor。
- 学习日报。
- 账号系统同步笔记、chat 历史、配置。

### 11.5 MVP 不做

- 手动编码。
- Agent 改代码。
- Git commit / branch / PR。
- GitHub 登录。
- 私有仓库。
- 本地目录导入。
- 语音输入。
- Skill marketplace。
- 高级商业化。
- ArkTS/ETS。
